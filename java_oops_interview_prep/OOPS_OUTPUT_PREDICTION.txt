ANSWER 1

  Child
Why: super() runs first, so the parent constructor body completes
before the child constructor body starts.

ANSWER 2
  Parent(int)
  Child()
Why: super(5) explicitly selects the parent's (int) constructor.

ANSWER 3
  Animal speaks
Why: Dog inherits speak() because it does not define one.

ANSWER 4
  20
Why: fields are NOT polymorphic. Inside Child, `x` refers to Child's
own field. (Use super.x to reach Parent's.)

ANSWER 5
  3
  6
Why: the compiler picks add(int,int) vs add(int,int,int) by argument
count at compile time.

ANSWER 6
  int
  long
Why: c.show(5) matches int exactly; c.show(5L) matches long.

ANSWER 7
  Child
Why: the object is a Child, so the override runs even though the
reference type is Parent.

ANSWER 8
  Parent
  Child
Why: super.who() explicitly invokes the parent version first, then
the child adds its own line.

ANSWER 9
  Bark
  Meow
Why: dynamic method dispatch - the runtime object type decides.

ANSWER 10
  Animal static
  Dog speak
Why: static methods bind at compile time by reference type (hiding);
instance methods bind at runtime by object type (overriding).

ANSWER 11
  static
Why: static methods do not need an object, so null is fine.

ANSWER 12
  Parent static
  Child static
Why: static methods are hidden, not overridden - the reference type
decides, so p.m() uses Parent even though p points to a Child.

ANSWER 13
  3
Why: count is static = one shared copy across all three objects.

ANSWER 14
  a.id=1 b.id=2 total=2
Why: count is shared and incremented by each constructor; id is a
per-object copy.

ANSWER 15
  static block
  instance block
  constructor
  instance block
  constructor
Why: static block runs once at class load; instance block runs
before the constructor body on EVERY new.

ANSWER 16
  Parent static
  Child static
  Parent instance block
  Parent constructor
  Child instance block
  Child constructor
Why: parents initialize first, top to bottom. Static blocks run at
class load, before any object is made.

ANSWER 17
  param x=10
  no-arg
Why: this(10) forwards to the (int) constructor, which runs first;
the no-arg body runs after.

ANSWER 18

Why: this.x -> Child's 20, super.x -> Parent's 10.

ANSWER 19

ANSWER 20

ANSWER 21

ANSWER 22

  20

ANSWER 23

ANSWER 34

ANSWER 35

ANSWER 36

Why: Integer caches -128..127, so a and b are the same cached

ANSWER 37

ANSWER 38
  Ravi

Why: `name = name` assigns the parameter to itself (the parameter

ANSWER 39
  done
Why: setting a reference to null only drops the reference; the
program just continues. (GC reclaiming the object happens later,

ANSWER 40
  Dog

ANSWER 41

even called. The contract is broken.

ANSWER 42
  String

type: String (child of Object). (Add an Integer overload and this
stops compiling - ambiguous.)
