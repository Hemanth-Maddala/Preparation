================================================================
DBMS INTERVIEW PREPARATION — LEARNING ROADMAP
================================================================
Purpose: Structured path to master DBMS for software engineering interviews.
Approach: Learn concepts → Understand why → Practice interview answers → Handle follow-ups
================================================================

==================================================
PHASE 1: DBMS FUNDAMENTALS
==================================================
Duration: 1-2 days
Priority: Foundation

Topics:
- What is a database?
- What is DBMS?
- Why do we need DBMS?
- DBMS vs RDBMS
- Database schema vs instance
- Metadata
- Database users and administrator
- Database system architecture

Goal:
  Be able to explain DBMS in 30 seconds.
  Answer "Why do we need DBMS?" clearly.

Practice Questions:
  Q: What is DBMS?
  Q: DBMS vs RDBMS?
  Q: What is schema?
  Q: Schema vs instance?

==================================================
PHASE 2: RELATIONAL MODEL + KEYS
==================================================
Duration: 2-3 days
Priority: Very High

Topics:
  Part A — Relational Model:
  - Relation, tuple, attribute, domain
  - Relation schema, relation instance
  - Degree vs cardinality

  Part B — Keys:
  - Super key
  - Candidate key
  - Primary key
  - Alternate key
  - Foreign key
  - Composite key
  - Natural key vs surrogate key

Goal:
  Explain every key type.
  Know relationships between keys.
  Answer "Can a table have multiple candidate keys?" confidently.

Practice Questions:
  Q: What is a primary key?
  Q: Primary key vs candidate key?
  Q: Can a table have multiple primary keys?
  Q: Can a foreign key be NULL?
  Q: What is a composite key?

==================================================
PHASE 3: CONSTRAINTS + ER MODEL
==================================================
Duration: 2 days
Priority: High

Topics:
  Part A — Constraints:
  - NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK, DEFAULT
  - Entity integrity vs referential integrity

  Part B — ER Model:
  - Entity, entity set, attribute
  - Relationship, relationship set
  - Strong vs weak entity
  - Attribute types (simple, composite, multivalued, derived, key)

  Part C — Cardinality & Participation:
  - 1:1, 1:N, M:1, M:N
  - Total vs partial participation
  - Junction tables for M:N

Goal:
  Draw ER diagrams mentally.
  Explain cardinality types with examples.
  Know when to use junction tables.

Practice Questions:
  Q: What is referential integrity?
  Q: What is total participation?
  Q: How do you implement many-to-many?
  Q: Strong entity vs weak entity?

==================================================
PHASE 4: NORMALIZATION
==================================================
Duration: 3-4 days
Priority: Very High (HIGHEST PRIORITY)

Topics:
  Part A — Foundation:
  - Why normalization?
  - Data redundancy
  - Insert, update, delete anomalies
  - Functional dependency
  - Partial dependency
  - Transitive dependency

  Part B — Normal Forms:
  - 1NF: Atomic values, no repeating groups
  - 2NF: No partial dependencies
  - 3NF: No transitive dependencies
  - BCNF: Every determinant is a super key
  - 4NF: No multi-valued dependencies
  - 5NF: No join dependencies

  Part C — Progression:
  Unnormalized → 1NF → 2NF → 3NF → BCNF → 4NF → 5NF

Goal:
  Explain the normalization progression.
  For each normal form, explain what it fixes.
  Answer "3NF vs BCNF?" clearly.
  Identify which dependency each normal form removes.

Practice Questions:
  Q: What is normalization?
  Q: What is functional dependency?
  Q: What is partial dependency?
  Q: What is transitive dependency?
  Q: Explain 1NF through BCNF.
  Q: 3NF vs BCNF?

==================================================
TIPS
==================================================

1. Don't memorize definitions. Understand concepts.
2. For every concept, ask yourself "Why?" and "When would I use this?"
3. Practice explaining concepts out loud.
4. Focus on Phase 4 (Normalization) — it's the most asked topic.
5. Always prepare for follow-up questions.
6. Don't skip the scenario questions — they test real understanding.
7. Review this roadmap daily before starting your study session.
8. After completing all phases, do a full revision using the main preparation file.
