================================================================================
              COMMON MISTAKES TO AVOID
================================================================================

1.  MEMORIZATION WITHOUT UNDERSTANDING
    Don't just memorize answers — understand the WHY behind each concept.
    Interviewers will ask follow-up questions.

2.  IGNORING FOUNDATIONS
    Skipping Phase 1-4 to jump to virtual memory is a mistake. Everything
    builds on processes, threads, and system calls.

3.  NOT PRACTICING CALCULATIONS
    Many interview questions require calculations (scheduling times, address
    translation, page table sizes). Practice by hand.

4.  CONFUSING SIMILAR CONCEPTS
    Common confusions:
    - Process vs Thread
    - Mutex vs Semaphore
    - Internal vs External Fragmentation
    - Deadlock vs Starvation
    - Paging vs Segmentation
    - Logical vs Physical Address
    - Contiguous vs Linked vs Indexed Allocation
    - Polling vs Interrupts vs DMA
    - Blocking vs Non-blocking I/O
    - Authentication vs Authorization

5.  NOT KNOWING THE FLOW
    Be able to trace complete flows:
    - System call flow (user mode → kernel mode → return)
    - Process creation flow (fork → exec → wait → exit)
    - Page fault flow (access → miss → disk I/O → page in → retry)
    - Context switch flow (save state → load state → resume)

6.  FORGETTING TRADEOFFS
    Every OS design decision has tradeoffs. Always mention pros AND cons.
    - SJF is optimal but causes starvation
    - Paging removes external fragmentation but adds internal fragmentation
    - Virtual memory enables larger programs but adds page fault overhead

7.  NOT DRAWING DIAGRAMS
    Visual representations help you think and communicate:
    - Process state diagram
    - Resource allocation graph
    - Page table structure
    - Memory layout

8.  GIVING LONG-WINDED ANSWERS
    Be concise but complete. Use the STAR method for scenarios:
    Situation → Task → Action → Result

9.  IGNORING REAL-WORLD EXAMPLES
    Connect concepts to real systems:
    - Linux uses preemptive scheduling
    - Unix uses inodes (indexed allocation)
    - Windows uses a hybrid kernel

10. NOT PREPARING FOR FOLLOW-UPS
    After each answer, think: "What would the interviewer ask next?"
    Prepare 2-3 levels of depth for each major topic.
